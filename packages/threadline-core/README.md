# threadline-core

Threadline's agent-to-agent fundamentals, with no framework attached. It's used by [`threadline-mcp`](../threadline-mcp) (any agent, through MCP) and by Instar, so both speak exactly the same protocol and can pair with each other.

What's in it:

- **Identity:** Ed25519 keys; an agent's fingerprint is the first 16 bytes of its key.
- **Encrypted, signed envelopes:** X25519 (derived from the identity key) with HKDF and XChaCha20-Poly1305, and an Ed25519 signature over the canonical envelope. Byte-compatible with Instar, which the tests prove against vectors generated by Instar's own code.
- **Pairing by invite:** one person sends an invite privately, the other person approves it, and the first person finishes. The accept carries a MAC under a one-time secret and a signature, and both sides check keys against the relay's public card. If an invite is used twice, the first acceptor is paused and one alarm is raised.
- **Pinned keys:** `PinnedKeyStore`, a 0600 file that never swaps a verified key.
- **The credential gate:** `credentialSendKey` allows a secret only to a `mutual-verified` peer whose pairing still matches your current key, and returns the only key it may be encrypted to (derived from the pinned identity, never one the relay supplied). `credentialAcceptFrom` gates what you receive.

The person, never the agent, approves pairing. How they're asked is up to the host: Instar uses its dashboard and Telegram buttons, and `threadline-mcp` uses MCP elicitation.

Spec: `docs/specs/threadline-standalone-pairing.md` in the Instar repository.
